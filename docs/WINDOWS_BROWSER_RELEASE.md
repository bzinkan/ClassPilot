# Windows Chrome and Edge release candidate

This branch starts from reviewed ClassPilot main `335123c8ff407446c5618e17a0c96ca94c82d157`, manifest 3.0.3. The older local 2.9.3 checkout is preserved and is not a release input. Windows artifacts use a separate four-part version (initial candidate 3.0.3.1) and separate Chrome/Edge public keys. The Chromebook manifest, identity flow and Store identity remain separate.

`npm run test:extension:windows` builds development ZIPs, verifies every file/hash and runs the actual packaged worker in disposable Chrome and Edge profiles against synthetic HTTP and a simulated native host. It tests guard pairing, exact source telemetry, existing-worker auth clear, local invalidation and credential isolation. These are unpacked development tests, not managed installation, signed native-host acceptance or physical OS lifecycle evidence. The Chrome-branded fixture uses its supported DevTools development loader; it does not modify the user's browser profiles or machine policy.

`npm run package:extension:windows` emits Chrome and Edge ZIPs plus a complete manifest under ignored `artifacts/`. It excludes local server overrides, environment files and private keys. Public fixture keys intentionally identify development extensions only; their private keys are not retained. Release packaging requires externally approved public keys, a separately versioned candidate and a clean reviewed source commit. No Store submission or publication is performed by these commands.

The shared worker enables Windows logic only in the generated artifact. It receives one-time proofs from `net.classpilot.guard` and exchanges them for its own memory/session-only browser bearer. It never receives the installation credential, guard bearer or PIN. The browser token is confined to `/api/classpilot/windows/browser/*`, its exact paired HTTPS origin and its opaque source/revision. Native-host failure immediately retires the channel and the existing authentication gate. Explicit browser sign-out also sends exact-profile/epoch local sign-out, retires the epoch durably and revokes the server guard. An old completion cannot authorize a new student. The Windows auth frame directs the student to enter their PIN in the native app.

Browser controls and tools continue through the shared implementations, with source-qualified transports and canonical policy/authority validation on the SchoolPilot side. Retired Focus behavior and school-disabled features remain disabled. Browser thumbnails use existing classroom observation leases for five-second active viewing and 30-second background capture; the Windows guard imposes an additional 45-second upper bound on every grant. Desktop viewing retains its separate authorization and approximately 30-second cadence.

Capability negotiation is a hard limit. Retired Live View remains disabled. Chromebook directory-continuity and kiosk-ticket capabilities describe the old identity bootstrap, which Windows replaces with native Guard/PIN pairing. The reviewed SchoolPilot baseline does not call its dedicated safety capture-request producer; Windows supplies the functioning exact ambient browser-evidence path and leaves that unused request capability unadvertised. Legacy observation-only compatibility and disabled read-only reporting screenshot paths are also unadvertised. Ordinary permitted browser thumbnails, URL classification and browser safety reporting use independent browser authority; Desktop pixels never enter those paths. Enabling an additional unsupported path requires implementation and validation before advertising it.

The managed package/runbook lives in sibling ClassPilotDesktop, `docs/WINDOWS_BROWSER_GUARD.md`. Its export-only policy template disables guest/private/additional profiles, restricts school accounts and prepares approved extension force-install settings. Organization application control is additionally required to restrict portable/unapproved browsers. Browser settings alone do not establish complete device coverage. Microsoft limits force-installation on Windows devices not joined to an Active Directory domain to extensions in Edge Add-ons; the school's actual deployment route must be proven ([Microsoft policy](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/extensioninstallforcelist)).

Pilot readiness remains false until the exact signed app/guard/host and approved browser artifacts pass one-PIN, managed installation, all enabled school capabilities, physical lifecycle, update/uninstall/rollback and resource tests on a suitable managed device. SchoolPilot Windows mode and Desktop visibility remain separate default-off gates. See the SchoolPilot integration reference for API, RLS, activation and rollback boundaries.
